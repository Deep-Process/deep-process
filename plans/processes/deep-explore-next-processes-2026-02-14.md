## Praktyczne Workflow'y i Integracje

### OPTION A: deep-compliance - Workflow

```yaml
PHASE 1: LOAD_ARTIFACT
  Input: AI-generated code/document/decision
  Process: Parse artifact, extract metadata (model, training data, decision chain)

PHASE 2: REGULATORY_MAPPING
  Map: artifact type → applicable regulations (EU AI Act, NIST, ISO)
  Example: Medical AI → High-Risk classification → FDA + EU MDR

PHASE 3: COMPLIANCE_CHECKS (gate-based)
  Gate 1: Transparency labeling (F-15)
  Gate 2: Bias audit (F-04)
  Gate 3: Training data disclosure (F-15)
  Gate 4: Operational evidence (F-18 - not screenshots)
  Gate 5: Human oversight checkpoints (F-03)

PHASE 4: EVIDENCE_GENERATION
  Output: Compliance report (PASS/CONDITIONAL/FAIL)
          Audit trail (who/what/when with evidence)
          Traceability map (artifact → requirements → regulations)

PHASE 5: REMEDIATION (if FAIL)
  Generate: Violation list (critical/required/recommended)
           Remediation checklist
  Re-verify: After fixes applied
```

**Integracja:**
- `deep-verify` → `deep-compliance`: Verify facts first, then check compliance
- `deep-risk` → `deep-compliance`: Risk assessment → compliance requirements
- `deep-architect` → `deep-compliance`: Design → compliance check → iterate
- `deep-document` → `deep-compliance`: Generate docs → compliance review

**Wzbogacenia:**
1. **Continuous Compliance Monitoring** - CI/CD integration (every commit → compliance check)
2. **Regulatory Change Alerts** - Monitor EU AI Act updates, auto-map to artifacts
3. **Compliance-as-Code** - Machine-readable policies (NIST_RMF_Measure_2_3 = check_bias_metrics())
4. **Cross-Industry Templates** - Pre-built dla FDA, EMA, FINRA (80% pre-built → 20% customize)
5. **Compliance Copilot** - AI assistant explaining "why this fails" + remediation suggestions

### OPTION B: deep-governance - Workflow

```yaml
PHASE 1: SYSTEM_INVENTORY
  Discover: All AI systems (models, agents, workflows)
  Map: Ownership, classification (high-risk vs low-risk)

PHASE 2: POLICY_DEFINITION
  Define: Governance policies (risk tolerance, bias thresholds, cost caps)
  Example: "No hallucination rate > 5% in production"
  Roles: Who can deploy/modify models

PHASE 3: GUARDRAILS_DEPLOYMENT (F-44: active defense layers)
  Input guardrails: Filter toxic prompts, PII leakage
  Output guardrails: Check hallucinations, bias, quality
  Verifier Agents (F-21): AI checking other AI's logic

PHASE 4: CONTINUOUS_MONITORING
  Monitor: Model drift, bias metrics, cost tracking, security alerts
  Alerts: Real-time (bias threshold exceeded, model suspended)

PHASE 5: GOVERNANCE_REPORTING
  Dashboards: Executive (AI risk posture, compliance status)
  Audit logs: Comprehensive, tamper-proof for regulatory inspection
  Trends: Is AI usage increasing risk over time?
```

**Integracja:**
- `deep-risk` → `deep-governance`: Score risks → monitor in production
- `deep-verify` → `deep-governance`: Verify claims → enforce in production
- `deep-compliance` → `deep-governance`: Check compliance → enforce continuously
- `deep-architect` → `deep-governance`: Design principles → maintain architecturally

**Wzbogacenia:**
1. **Verifier Swarm Architecture** - Specialized verifiers (Logic, Bias, Hallucination, Security)
2. **Governance Policies as Code** - Git-based (version control + code review)
3. **Automated Remediation** - Auto-fix when possible (drift → retrain, bias → suspend)
4. **Governance Copilot** - "Why was my model flagged?" + fix suggestions
5. **Cross-System Correlation** - Detect patterns across models (shared training data issues)
